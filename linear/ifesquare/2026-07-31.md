## 1. Backend — Listings pagination + server-side search (`soldbay-web`)

### Goal
`GET /api/listings` returned **every** active listing in one response. As listings grow this becomes a memory/latency problem and makes the mobile feed progressively slower.

### Changes
- `soldbay-web/src/app/api/listings/route.ts`
  - Cursor-based pagination: `?limit=&cursor=` with `DEFAULT_LIMIT = 20`, `MAX_LIMIT = 100`.
  - Fetch `limit + 1` rows, slice to `limit`, return `{ items, nextCursor, hasMore }`.
  - `nextCursor` is the last item's `id`; client passes it back with `skip: 1`.
  - Added `?search=` — case-insensitive `title`/`description` `contains` filter.
  - Ordering hardened to `[{ createdAt: "desc" }, { id: "desc" }]` (stable cursor with unique tiebreaker).

### Status
**Complete.** Response shape changed from `Listing[]` → `{ items, nextCursor, hasMore }`; only consumer is the mobile app (updated in §4).

## Follow-up: Login 500 on Expo web (post-session bug)

### Symptom
- Expo web (`localhost:8081`) repeatedly logged `Web ERROR Login error: [ApiError: Something went wrong. Please try again.]` from `login()` → `POST /api/auth/mobile-login`.

### Root cause
- `next dev` server log (`.next/dev/logs/next-development.log`) showed the real errors:
  - `Mobile login error: Error: Connection terminated due to connection timeout` (dominant, ~13 occurrences)
  - `Mobile login error: ...read ENETUNREACH` (transient network)
- The `connectionTimeoutMillis: 5_000` added in the earlier pool config was too tight: cold connections through the Prisma Postgres proxy (`db.prisma.io`) spike past 5s. Measured standalone cold connects: 1.2–2.0s, occasionally slower. When the pool went cold after idle, the 5s cap aborted the connect → 500 on `/api/auth/mobile-login`, `/api/categories`.
- Verified the adapter (`@prisma/adapter-pg` `index.js:785`) passes config straight to `pg.Pool`, so the timeout is honored.

### Fix
- `soldbay-web/src/lib/prisma.ts`: `connectionTimeoutMillis: 5_000 → 15_000`, `idleTimeoutMillis: 20_000 → 60_000` (keeps connections warm longer, fewer cold reconnects). `max: 10` unchanged.
- Restarted `next dev` (globalThis caches the PrismaClient, so HMR alone would keep the old 5s config). Now running detached: `nohup npx next dev > /tmp/opencode/soldbay-web-dev.log 2>&1` (pid 74269, port 3000).

### Verification
- 5 sequential `POST /api/auth/mobile-login` (nonexistent email) → all HTTP 401, zero errors in fresh log.
- `GET /api/categories` → HTTP 200. `tsc --noEmit` clean.
- Change is uncommitted; dev server for `soldbay-web` now runs under nohup (log at `/tmp/opencode/soldbay-web-dev.log`) instead of a live terminal.
